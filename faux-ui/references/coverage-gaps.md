# Coverage Gaps

- **Single source.** Every rule and number comes from Stageshow. The library's bar for a top-level skill is normally two or three independent sources; this one was admitted because the task shape is narrow, absent from the library, and the source is unusually specific. A second practitioner's account of marketing product shots (Stripe, Linear, and Vercel publish none as agent guidance that was found) would let the single-source numbers be confirmed or scoped.
- **Kit path run twice, not evaluated.** A hero loop and a bento were built with the upstream kit installed (see sources, Local comparison) and both passed the upstream gate. Neither had a fresh-eye review, a states sheet, a dark pass, or a handover note, and the hero's motion runs were `inconclusive`. There is no blind comparison of kit against no-kit on equal model and effort.
- **The no-kit path has two exemplars and no more.** `examples/still-hero.html` and `examples/bento.html` give the fallback path something to copy (see sources). There is no animated exemplar, no phone, no dark theme, and only two of the seventeen layouts; a brief outside those still starts from rules alone, which is where builds came out oversized and heavy.
- **Eval is thin.** Three cases under `evals/`, built once per arm per round on 2026-11-18 and graded blind from rendered images. Round 2, against the current skill and graders: 17/18 with the skill, 8/18 without (details and both rounds in `docs/skill-evals-2026-11.md`; renders in `docs/evidence/faux-ui-evals-2026-11/`). One grader per case, one model, and assertions written by the skill's editor. Still broken in the skill run: a name and a ticket title repeated across bento tiles, more than one gap under tile copy, and a file row cut mid-text by the stage edge.
- **Rehearsal is skipped when it is not cheap.** Round 1's loop builder did not film the loop and shipped a clipped label. After `scripts/contact-sheet.mjs` was added, round 2's builder filmed it. That is one observation each way.
- **Upstream parts read only in part.** The kit reference (component props and rules), the last third of the annotations and rehearse references, and the teaching pairs' source were skimmed or skipped. The 71 example folders were not opened; the layout table names what each teaches.
- **Kit and script safety.** A static read found no concerns (see sources, Security read), but it was pattern-searched rather than read line by line for the larger modules, no dependency source was read (including `portless`), and nothing was executed. Repeat the read when the upstream revision changes.
- **Not React.** The rules are stack-neutral in principle, but every upstream example is React with plain CSS. Nothing here has been tried in SwiftUI, a video tool, or a canvas.
- **Accessibility of the demo itself.** Upstream covers reduced motion, a poster frame, and the no-headings rule. It says little about how a decorative demo should be exposed to assistive technology (hidden with a text alternative, or labeled), about pause controls for loops longer than five seconds, or about contrast inside the miniature. Route those questions to `web-design` (web-accessibility) and record the answer here.
- **Performance on the host page.** Several looping stages on one page, offscreen pausing, and layout cost of runtime measurement are mentioned upstream but not quantified.
- **Brand and trademark use.** The guidance to use real, current marks is operational. Whether a given use of another company's mark or interface is permitted is a legal question this skill does not answer.
- **Illustration and photography.** Out of scope by design: the source says plainly that it cannot draw. `frontend-design` holds what the library has on hand-written SVG illustration.
- **Model drift.** The author expects some rules to become unnecessary as models improve and reports that early rules about traffic-light sizing already did. Nothing here records which rules still change the result on current models.
- **The contact-sheet script only takes pictures.** It has none of the upstream film script's measurements (jumps, gutters, insets, clipped glyphs), so every named fault is still found by eye. Its smoke test (`scripts/contact-sheet.test.mjs`) covers cropping, the viewport, load failures, and loop-length frame counts on one machine with one browser.
