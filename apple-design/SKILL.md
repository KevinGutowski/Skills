# Apple Platform Design

**Sources/gaps:** [references/sources.md](references/sources.md) maps the local Apple source corpus; [references/coverage-gaps.md](references/coverage-gaps.md) lists platform areas that need live HIG/doc verification before becoming reusable rules.

Read exactly one reference file below; each carries the full distillation for its area. **Second-hop pattern:** deeper worked examples, code and source lists live in a same-named subdirectory next to the reference (`references/<name>/…`). Each bullet names its second-hop files; open one only after its parent reference, which links it and says when it is needed. Nothing lives deeper than that.

**Apple's Xcode skills first:** Xcode 27+ bundles first-party agent skills. If `xcrun` exists, run `xcrun agent skills export` and apply the matching skills (Apple's wins on conflict); otherwise read the pinned mirror. Full procedure, pin (Xcode 27.2 27B52) and which skill fits which work: [references/xcode-agent-skills.md](references/xcode-agent-skills.md) — read it at the start of any Apple-platform implementation task; `uikit` and `swiftui` point here too.

**Boundary splits to respect:**
- **Implementation and platform craft → `swiftui`** — this skill decides the design; SwiftUI code, gestures, widgets, SF Symbols, animation engineering live there. **UIKit code → `uikit`** (collection views, scroll position, traits, menus, iOS 27 SDK migration).
- **Canonical current specs → [references/hig.md](references/hig.md)** — talk-derived references here carry reasoning and craft; when you need Apple's exact letter-of-the-law spec (or a staleness tiebreaker), fetch the live HIG via that playbook.
- **Typography split:** Apple platforms → this skill's apple-typography reference; web/CSS → `web-design` (web-typography). Never cross-apply platform conventions.
- **Accessibility split:** Apple platforms → this skill's apple-visual-accessibility reference; web → `web-design` (web-accessibility) (same split as typography).
- **Installed websites stay web:** iOS/iPadOS Home Screen apps and macOS Add to Dock sites route to `web-design` (apple-installed-web-apps), not to native HIG or SwiftUI implementation guidance.
- **Principles translate; specs don't.** Apple's interaction *principles* (fluid response, interruptibility, momentum, spatial consistency — `swiftui` (touch-interaction-design)) and its eight design *values* (`design-principles`) are platform-agnostic and carry to the web, where `web-design` (web-animation-design) and `design-craft` (emil-kowalski) are their homes. Only the platform-specific *specs* — type tracking, a11y APIs, component conventions, the Liquid Glass material — must never cross-apply.
