# Frontend Design

**Mode: build.** Implement the requested component, page, or app in the user's stack. Do not stop at a mood board, design critique, or code sketch.

**Boundary:** this skill owns new bold/distinctive web UI. For restrained polish use `design-craft`; for web craft rules or motion values use `web-design`; for diagnosis of UI already generated by AI use `working-with-ai` (ai-ui-direction); for procedural artwork use `creative-coding`. If bold and restrained themes are both plausible, present the choice instead of blending them.

## Fast path: six decisions

0. **Mode:** name what the visitor's success looks like on *this surface*. Persuade means decide and act (landing, pricing). Operate means complete a task (app UI, dashboards, settings). Read means understand (docs, articles). Experience means the work leads (portfolios). Pick the mode from the surface, not the product. Persuade and Experience get full, committed ambition. On Operate and Read, ambition shows as precision and restraint, and the world lends only type, palette, density, and one signature move. Details: [references/surface-modes.md](references/surface-modes.md).
1. **Purpose:** identify the user, job, content, and technical/accessibility constraints. Decide what is already true. **Refinement preserves** the incumbent identity, copy, and everything out of scope. **Redesign replaces** the look but keeps product truth, and never polishes the discarded look. A local addition inherits its surface.
2. **Concept:** commit to one context-specific idea and one memorable device. On a new world, list seven concrete candidates from the audience's world, then by default let something other than your own ranking pick (the user, a draw, a seed), because the model's favorite from its own list tends to be the category default. This is an experimental default from one project's evaluation, not a hard rule. Skip it when the brief pins a direction, for extensions and narrow refinements, or when the user wants to choose freely or wants the familiar category standard. Borrow the form's skeleton, not its clothes.
3. **System:** choose a color *strategy* (Restrained / Committed / Full palette / Drenched) before colors. Then define type roles, tokens, spacing/radius rules, composition, imagery, and interaction states before adding decoration.
4. **Truth:** make the hero demonstrate the real product mechanism with internally consistent data. Demo data may be authored and labeled synthetic, but prices, customers, benchmarks, and capabilities are never invented.
5. **Delivery:** implement the complete experience, then inspect it at real size and under responsive, interaction, content, and accessibility stress.

**The brief wins.** Honor pinned aesthetics, eras, fonts, and palettes even when they match a known tell. Where the brief leaves the aesthetic open, reject unconsidered defaults. The named tells are kicker/eyebrow labels (a ban), side-stripe borders, gradient text, purple/neon palettes, reflex cream grounds, glow halos, icon tiles above headings, nested cards, identical card grids, and reflex display faces; the full catalog with detector IDs is in [references/anti-slop-catalog.md](references/anti-slop-catalog.md). Also self-check against the four saturated looks (cream + italic serif + terracotta, near-black + neon glow, hairline broadsheet + mono labels, default neobrutalism): if someone could guess your aesthetic from the category alone, rework it. A system font is acceptable when the artifact must be single-file and offline, and on Operate/Read surfaces generally. Otherwise prefer a distinctive licensed or open face that can actually ship.

## Build contract

1. Establish a short concept statement: audience/job → aesthetic direction → memorable device. For a new or replaced world, write the six-block direction contract (THESIS, OWN-WORLD, STORY, FIRST VIEWPORT, FORM, FINISH) in a dev-only brief, never in shipped source.
2. Build on accessible standard controls; theme their visual layer rather than recreating behavior.
3. Implement working code with the requested states and interactions. Match implementation complexity to the concept: maximalism may require more machinery; refined minimalism requires restraint and precision.
4. Keep decorative motion finite and purposeful. Use the owning `web-design` motion rules when exact values are needed.
5. Commit first, then clarify. Rebuild every atom (nav, buttons, inputs) in the chosen vocabulary. Later passes sharpen clarity and never dilute the concept.
6. Return **concept → implementation → verification**. Name the files changed and the checks actually run.

## Verification

Before claiming completion:

- Run the craft floor in one batched look at the render: contrast, depth, spacing rhythm, type measure and steps, motion, states, themed browser surfaces (selection, caret, scrollbars, focus rings), and brief coverage ([references/anti-slop-catalog.md](references/anti-slop-catalog.md)). Batch fixes. Self-inspection stops after two rounds; after that, repairs come only from the reviewer's verdict (below).
- Exercise the primary task and every requested interaction/state.
- Inspect the rendered result at target sizes; test narrow/wide containers, long or localized text, and user text scaling.
- Verify keyboard operation, visible focus, semantics, contrast, reduced motion, and overflow behavior.
- Confirm the focal demonstration is truthful and the console has no new errors.
- For a new world or a full surface, get an independent fresh-context review against the direction contract and screenshots before calling it done. Then act on its verdict: **recapture** (invalid evidence; recapture and re-review), **rebuild** (re-derive the failed regions, then a full re-review), **fix** (one fix batch, recapture the same viewports, have the reviewer score each fix), or **ship**. If no subagent is available, run a separate pass from the screenshots and contract only, and say in the report that the review was not independent ([references/surface-modes.md](references/surface-modes.md), Finish).
- If visual inspection or browser execution is unavailable, state that limitation instead of claiming visual completion.
