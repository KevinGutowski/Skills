Reduced motion is handled: either the code gives a crossfade or static swap under prefers-reduced-motion, or the answer uses a library path it states handles the setting itself. The same holds for missing WebGL when WebGL is used, and the result is complete without the effect; the in-progress payment state is shown by visible text or a visible label change that does not rely on motion (aria-busy or a hidden status region alone does not pass), and the outcome is announced through a role="status" or role="alert" region or by moving focus to the receipt.
