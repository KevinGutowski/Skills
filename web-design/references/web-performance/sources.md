# Sources

- *"Betting on the web: ensuring fine-tuned performance for dynamic web apps" — Charlton Roberts, frame.io/Adobe (Vercel conference; surfaced via Emil Kowalski's animations.dev Vault). The fluid-UI process discipline.*
- *"Crossing the chasm between quality and performance" — Ricardo Vazquez (Dropbox, ex-Shopify POS), Figma Config 2025. The metrics-and-principles layer.*
- *Supporting field sources: Josh Wootonn's sidebar-performance study; Henry Heffernan and Dennis Brotzky (animations.dev interviews); Henry Modisett (Perplexity, Config 2024).*
- *performance.dev (Dennis Brotzky, 2026): the Linear, ChatGPT, Conductor, and Wealthsimple breakdowns — the constraints-first architecture rule and Linear's timing tokens (cited in web-animation-design); the Rails equivalents live in `rails` (optimizing-rails, perceived-speed).*
- *Dmytro (@pqoqubbw, Mintlify), "4 css rules that make safari 35x faster" — X article 2122725135098814464 (post 2122725141285364024, 2026-11-17), with its agent prompt gist (https://gist.github.com/pqoqubbw/a5d168f571d0283269f2987a7de3728f). The Base UI Scroll Area workaround for WebKit bug 325900. Checked against Base UI's `ScrollAreaViewport.tsx` on `master` (2026-11-18) and the Scroll Area docs page. A temporary workaround, tracked in the web-design coverage gaps.*
- *Rida F'kih, "Bypassing iOS Safari's 60 FPS Limit to Build Web Applications That Feel Native" (https://rida.dev/blog/bypassing-ios-safari-60-fps-limit, 2026-11-20; shared in X post 2124325907058053256, 2026-11-22). It covers the 60 Hz `requestAnimationFrame` and input cap, scroll containers as 120 Hz input, the `OffscreenCanvas` presentation route, and 240 fps slow-motion benchmarking. This is the "iOS Safari's 60 Hz cap" section. Single author, measured on his own devices; the scroll-polling and refresh-rate-boost tricks were left out as fragile.*
- *Devon Govett, "Scrolling is All You Need: Building a Swipeable Sheet" (React Aria blog, https://react-aria.adobe.com/blog/sheet, 2026-10-08). The compositor route: scroll snap plus view timelines, with gestures off the main thread at the native refresh rate. It independently corroborates F'kih's premise.*
- *WebKit bug 307554, "[threaded-animations] only opt animations affecting transform into high frame rate on iOS" (https://bugs.webkit.org/show_bug.cgi?id=307554, fixed 2026-02-12 in 307339@main; read through the Bugzilla REST API, 2026-11-22). The primary evidence that only `transform` animations, not `opacity` or `filter`, get a high frame rate on iOS. A QA pass flagged it after the first version of the 60 Hz section said all compositor animations run at full rate.*
