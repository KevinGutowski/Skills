# Sources

**Sources:**
- *Laura Kalbag, Accessibility for Everyone (A Book Apart, 2017)* — the spine: practice, priority order, testing, org layer
- *Michael J. Metts & Andy Welfle, Writing Is Designing, ch. 5 "Inclusivity and Accessibility" (Rosenfeld, 2020)* — the writing-accessibly layer
- *Adham Dannaway, Practical UI (2nd ed., 2024)* and *Wathan & Schoger, Refactoring UI* — the contrast-metrics layer (§5b)
- *W3C WAI, WCAG 2.2 Understanding documents* — current Focus Not Obscured, Focus Appearance, and Target Size distinctions: https://www.w3.org/WAI/WCAG22/Understanding/
- *W3C WAI, What's new in WCAG 2.2, and the Understanding documents for 2.5.7 Dragging Movements, 3.2.6 Consistent Help, 3.3.7 Redundant Entry, 3.3.8 Accessible Authentication (Minimum), and 4.1.3 Status Messages* — https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/ · https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html · https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html · https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html
- *W3C WAI-ARIA APG, Dialog (Modal) pattern* — focus in, Tab containment, Escape, return focus: https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/
- *GOV.UK Design System, Error summary* — focus to the summary after a failed submit: https://design-system.service.gov.uk/components/error-summary/
- Located through `ui-ux-pro-max` (nextlevelbuilder, MIT, rev `6ec2bb5`), whose UX guideline rows 100–109, 118, and 141 cite these documents; the official pages are the authority.
- *W3C WAI, ARIA Authoring Practices Guide, Developing a Keyboard Interface* — native-vs-custom keyboard behavior and composite-widget focus conventions: https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/
